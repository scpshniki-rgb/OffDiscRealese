# OffDisc — GitHub Pages + аккаунты

Этот пакет содержит клиент OffDisc для GitHub Pages и отдельный backend авторизации на Cloudflare Workers + D1. Регистрация и каждый вход подтверждаются одноразовым кодом на email через Resend.

## Что добавлено в интерфейс

- 10 дополнительных цветовых схем (всего 17 цветовых схем), каждая в тёмном и светлом варианте.
- Окно настроек занимает около 75% ширины и высоты экрана на desktop; на небольших экранах адаптируется к размеру окна.
- Регистрация по логину, email и паролю.
- Подтверждение email при регистрации.
- Вход по логину или email + пароль + одноразовый код из письма при каждом новом входе.
- Просмотр состояния аккаунта и выход из аккаунта в **Настройки → Мой аккаунт**.
- Гостевой режим остаётся доступен, пока backend не настроен или пользователь не вошёл.

## Важно про данные

Cloudflare D1 в этой сборке хранит учётные записи, PBKDF2-хэши паролей, хэши одноразовых кодов и сессии. Данные чатов, серверов и часть профиля в текущем приложении по-прежнему хранятся локально/MQTT. Эта авторизация пока не переносит историю сообщений и состав серверов в облачную БД.

## Часть 1. Развернуть backend аккаунтов

Нужны аккаунт Cloudflare и домен отправителя в Resend. Cloudflare Workers запускает API, D1 хранит учётные записи, Resend доставляет письма с кодами.

### 1. Создай D1 базу

В папке `auth-worker` выполни:

```bash
npm install
npx wrangler login
npx wrangler d1 create offdisc-auth
```

Wrangler покажет `database_id`. Открой `auth-worker/wrangler.toml` и замени:

```toml
database_id = "REPLACE_WITH_D1_DATABASE_ID"
```

на настоящий ID, который вернул Cloudflare.

### 2. Примени схему

Из папки `auth-worker`:

```bash
npx wrangler d1 migrations apply offdisc-auth --remote
```

### 3. Настрой email

В Resend подтверди домен отправителя и создай API key. Укажи реальный подтверждённый адрес отправителя в `EMAIL_FROM` в `wrangler.toml`, например:

```toml
EMAIL_FROM = "OffDisc <no-reply@твой-домен.ru>"
```

Не используй адрес, который не подтверждён в Resend.

Добавь секреты Worker (не записывай их в GitHub):

```bash
npx wrangler secret put RESEND_API_KEY
npx wrangler secret put OTP_PEPPER
```

Для `OTP_PEPPER` введи длинную случайную строку (не менее 32 случайных байт). Она используется для хэширования одноразовых кодов. Не теряй её и не публикуй.

### 4. Разверни Worker

```bash
npx wrangler deploy
```

После публикации появится URL примерно такого вида:

`https://offdisc-auth.ТВОЙ-SUBDOMAIN.workers.dev`

Проверь его в браузере, добавив `/health`. Должен вернуться JSON с `ok: true`.

### 5. Разреши GitHub Pages origin

В `auth-worker/wrangler.toml` по умолчанию разрешён текущий origin GitHub Pages:

`https://scpshniki-rgb.github.io`

Если Pages будет на другом домене — обнови `ALLOWED_ORIGINS` (без завершающего слеша), затем снова выполни `npx wrangler deploy`.

## Часть 2. Подключить frontend

1. В корне сайта рядом с `index.html` скопируй `offdisc-config.example.js` в файл `offdisc-config.js`.
2. Открой `offdisc-config.js` и замени `YOUR-SUBDOMAIN` на реальный subdomain Worker.
3. Загрузи в корень GitHub Pages репозитория:
   - `index.html`
   - `offdisc-config.js`
   - `.nojekyll`
4. Не загружай `auth-worker` внутрь публичного сайта как доступный API-код с секретами. Папку можно хранить в репозитории исходников, но секреты должны оставаться в Cloudflare Worker Secrets.

После обновления страницы открой **Настройки → Мой аккаунт → Войти / Создать аккаунт**.

## API endpoints

- `POST /auth/register` — создать неподтверждённую учётную запись и отправить код.
- `POST /auth/login` — проверить логин/пароль и отправить код второго фактора.
- `POST /auth/verify` — проверить одноразовый код и выдать сессию.
- `GET /auth/me` — получить текущую учётную запись по Bearer-токену.
- `POST /auth/logout` — завершить текущую сессию.
- `GET /health` — health check.

## Меры безопасности

- Пароль никогда не отправляется в email и не сохраняется открытым текстом.
- Пароли хэшируются на Worker с PBKDF2-HMAC-SHA-256 (310 000 итераций, уникальная соль).
- Одноразовые коды действуют 10 минут, допускают максимум 5 проверок и хранятся в виде хэша с секретным pepper.
- Сессии используют случайные bearer-токены; в D1 хранится только SHA-256-хэш токена; срок сессии — 14 дней.
- Включён простой rate limit по IP для регистрации, входа и проверки кода.
- CORS ограничен origin GitHub Pages и localhost для локальной проверки.
- Секреты Resend и OTP pepper должны храниться только в Cloudflare Worker Secrets.

Перед публичным запуском стоит добавить CAPTCHA/Turnstile, восстановление пароля, управление активными сессиями и полноценную облачную синхронизацию данных приложения. Этот backend — минимальный безопасный старт для аккаунтов, не полный backend всего мессенджера.
